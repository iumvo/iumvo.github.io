TICKET-011 (bug-fix session)
Status: done

User report (verbatim):
- "A default room name and a default user name generation disappeared. Be careful, look up the
   history of changes. Revert this. It must be generated by default as you once did."
- "Critical problem: see folder 'bugs'. Creating a room doesn't provide me with any text to share,
   and no controls are visible. Full attention. If cannot solve, investigate, and write your guesses
   why it happens. Nothing else matters until it is fully resolved. Is it a problem with planning?
   What fails?"

Problem:
- After pressing "Create room" the page showed nothing at all (no lobby, no room controls).
- The default nickname ("Kabanchik###") and default room name ("IUMIUMIUM") were gone.

Investigation (evidence, not guesses):
1. The file saved by the user in bugs/bug1/ is a serialised live DOM. It shows:
     <section class="card hidden" id="lobby">   <- lobby hidden
     <section class="card hidden" id="room">    <- room hidden
   Both sections hidden => the page is blank. This is the exact state the user reported.
   The DOM also contains a generated offer SDP and two peer cards, i.e. the script did run and
   the offer text *was* created - it was just never visible.
2. Replaying the session-01 build in a headless DOM reproduces that state byte for byte
   (lobby hidden + room hidden + getElementById("room") returns an <INPUT>).
3. Replaying the session-02 build produces:
     Uncaught [ReferenceError: Cannot access '$' before initialization]
   -> the whole <script> aborts on the first statement that uses it.

Root causes (two independent bugs):
A) DUPLICATE DOM ID "room"
   The lobby had <input id="room"> (the room-name field) and the room view had
   <section id="room">. getElementById() returns the FIRST match in document order, i.e. the
   input. So enterRoom() executed `$('room').classList.remove('hidden')` on the *input* and the
   room section kept class="hidden" => the room was never shown, while the lobby was hidden =>
   blank page. leaveRoom() had the mirror-image bug.
   This bug existed since the very first commit (all versions in git history contain it) and was
   the true cause of the original "no offer text after Create room" complaint in session 01:
   the offer was generated, but inside a display:none section.
B) `const $` USED BEFORE DECLARATION (introduced in session 02, ticket009)
   The theme block called $('btnTheme') ~6 lines before `const $ = id => ...` was evaluated.
   `const` is in the temporal dead zone there => ReferenceError => the entire IIFE died.
   Everything after line 173 never ran: the default nickname/room generation, all button handlers
   (Create did nothing at all), the theme toggle, the room link, the latency poll.
   That is why the defaults "disappeared" - the code was still there, it just never executed.

Plan:
- Backup to backups/backup011/ (index.html + README.md).
- Move `const $ = ...` to the top of the script; delete the later duplicate declaration.
- Rename the lobby input to id="roomInput" so the room section owns the id "room" alone.
- Restore the default generation explicitly (nickname regenerated on every load, room = IUMIUMIUM,
  a ?room= link still wins) and add a "🎲 Another name" button.
- Make "Create room" open the room FIRST and request the microphone afterwards, so a blocked mic
  can never prevent the offer text from appearing.
- Add a visible error banner (window.onerror / unhandledrejection) so a script error can never
  produce a silent blank page again.
- Render peer cards in place (create-once rows) so text pasted by the user is never wiped by a
  re-render triggered by an ICE state change.
- Build tools/selftest.mjs: a headless (jsdom) regression test that runs the real index.html.
- Re-run the test against the old builds to prove it detects both bugs.
- Update README (usage + troubleshooting + tests), write feedbacks/session03.txt.

Summary:
- Both root causes fixed; the room is always visible after "Create room" and always offers
  shareable text, with or without a microphone.
- Default nickname (Kabanchik###) and default room name (IUMIUMIUM) are generated again, plus a
  regenerate button for the nickname.
- tools/selftest.mjs: 46 checks, all green on the fixed build; the same test fails loudly on the
  session-01 and session-02 builds (it reports the ReferenceError and the blank room).
- Backup saved to backups/backup011/.
- The page can no longer go blank silently: any script error is shown in a red banner at the top.
